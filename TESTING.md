# План интеграционного тестирования

Unit-тесты выполняются командой `gradle test`. Для приёмки разверните один Velocity 4.3.0 и минимум два Purpur backend с ChatViramble.

1. Отправьте `Привет` и ` !Привет`: видимость и формат должны остаться локальными.
2. Отправьте `!Привет`, `! Привет`, `!!Привет`: все онлайн-игроки получают соответственно `Привет`, `Привет`, `!Привет` один раз.
3. Отправьте `!` и `!   `: только отправитель получает ошибку.
4. Проверьте cooldown 3 секунды, одинаковый текст в течение 10 секунд и bypass permission.
5. Проверьте 256 и 257 Unicode code points, emoji и кириллицу.
6. Отправьте `<red>текст</red>`: теги должны отображаться буквально.
7. Перейдите между backend-серверами и повторите отправку; дублей и отложенной доставки быть не должно.
8. Выполните reload/status/toggle с разрешениями и без них; перезапустите Velocity после toggle.
9. Остановите одного получателя во время рассылки; остальные должны получить сообщение.
10. Проверьте клиентом целевой версии с `enforce-secure-profile=true`: в логах не должно быть `FATAL`, `illegal protocol state` или ошибок acknowledgement.
11. Удалите backend JAR на тестовом сервере: локальный чат продолжает работать; `!` не может безопасно стать глобальным. Верните модуль.
12. Задайте неверный secret: глобальное сообщение отменяется backend, Velocity отклоняет пакет и пишет диагностику; локальные сообщения работают.

Колонки для протокола приёмки: дата, версии Velocity/Purpur/ChatViramble, шаг, фактический результат, лог/скриншот, ответственный. Без доступа к живой сети пункты 1–12 нельзя честно пометить как фактически пройденные.
